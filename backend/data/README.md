# backend/data/ —— 运行时数据（人核产物，**不是代码**）

## ref_allowlist.json —— 跨文档引用跟随白名单（阶段 2b）

`backend/refs.py` 运行时**只读这个文件**，一行正则都不跑。正则（`refs.extract_refs`）
只是**离线生成候选队列**的生成器 —— 队列必须**人核**（铁律 6：关键字定位实测 9/14 找错款）
之后才写进这里。

### 为什么不能运行时跑正则直接跟

书名号里的东西**大量不是文档**：课程名（《机械设计》《最优化方法》）、外校文件
（《XX大学学生管理规定》）、表格名。`coverage._DOC_SUFFIX` 的尾词过滤只是**降低**误伤，
不是消除。跟随是**已核验事实**，不是推断。

### 格式

```json
{
  "version": 1,
  "names": {
    "本科生课程认定暂行办法": {"note": "转专业办法第十六条引用；人核 2026-10-08"}
  }
}
```

- **键 = 归一名**，必须与 `coverage._norm` 同口径（去校名前缀、去尾部括号、去空白与书名号）。
  即「《桂林电子科技大学本科生课程认定暂行办法》」的键是 `本科生课程认定暂行办法`。
  别手算 —— 用 `python -m refs --norm "《…》"` 打印。
- **值里的 `document_id` 故意不写**（见下），`note` 只给人看，代码不读。
- 人核要确认的是：源文档正文里**确实**有「按/参照/依据/根据…《X》」这处引用，
  且**跟随它是有用的**（X 是配套办法、补充规定这类需要一并看的文件；
  只是顺带提及 X 的，不必收）。

### 为什么存名字不存 document_id

`document_id` 是**建库时分配的序号**，重新入库（换语料 / 重跑 ingest / 换 collection）后
**全变**。把 id 固化进人手核过的文件，重库一次就变成「按名字查到了、id 指向别的文档」——
**跟错文档比不跟更糟**：模型会拿一份不相干的文件冒充依据。所以运行时按名字解析
（`coverage.load_corpus_index` 的 `ids`），重库后照样对。

> ⚠️ 副作用：键写错 = **静默失效**（查不到、不报错）。
> 唯一的防线是 `python -m refs --check`（在服务器上跑，能连 Qdrant）——
> 逐条报告名单里在语料中找不到的键。**建完白名单必跑一次。**

### 行为与失败模式

- 文件不存在 / JSON 坏 / `names` 不是 dict → `load_allowlist()` 返回 `{}`
  → 跟随**和**「缺失提示」**整个自动关闭**（铁律 12：失败开放，退回旧行为）。
- 白名单非空时，`refs.missing_refs()` 还会把上下文里**被引用、但语料中不存在**的文件
  （如《考勤办法》《实验教学工作条例》）交给提示词，让模型**明说这份没收录**而不是
  照着文件名编内容。
- 跟随上限：一跳、≤2 份文档、≤4 块、≈1600 字（见 `refs.py` 模块头 —— 上限刻意压小，
  免得被引用的整份办法把 `max_context_chars` 预算吃光）。
- ⚠️ 本文件**不进代码发布流**，部署（含容器镜像）必须单独拷。漏拷 = 功能静默关闭。
- ⚠️ 重新入库后 document_id 会变 —— 调 `refs.reset_cache()` 或**重启服务**
  （`start_all.sh` 的流程本就是入库后重启）。

队列生成与人核流程见 `训练集/_work/tutor/`（执行顺序第 4 步）。
