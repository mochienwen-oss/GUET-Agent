## 2. 当前工作原则

- 以具体问题和项目收益为依据，不为提高表面数据而改口径、堆规则或删必要条件。
- 明确区分：工程流程可运行、模型语义正确、检索充分、机械校验通过、实际文件视觉合格。这些不是同一个结论。
- 每项修复有直接检查和明确停点；不承诺“以后不会出现新问题”。
- 已批准的普通本地工作直接推进，不反复申请同一设计。新付费调用、服务器范围及用户要求先确认的删除须遵守相应边界。
- **测试程序自然结束后统一读取结果，不实时grep或查看中途答案。** 不反复采样挑选好答案。
- 最小必要修改，不顺手重构，不默认增加基线、哈希、探针、额外门禁或全量审计。
- 学校事实依据真实材料；用户材料仅归当前任务，历史助手回答不自动成为事实来源。
- 遵循项目AGENTS.md及用户编码规范；清理不等于授权删测试、知识资产或开发辅助框架。

## 3. 当前架构与职责

### 3.1 主链路

```text
Vue聊天 → POST /api/chat
  → 身份、会话归属与并发检查
  → 最近消息 + 持久化ConversationContext
  → LangGraph主图
       规则层 → 实体/范围解析 → 上下文层 → API规划
       → 统一提交调用 → 参数/范围/Skill验证 → Registry执行
       → 追加真实工具证据 → 有限调查或收尾
       → 应用层决定补问、缺依据、计算或成文
       → API组织正文 → 引用/枚举/计算等机械检查
  → SSE交付 → 正文与来源落库 → revision约束的会话状态更新

PPT能力交接或网页制作表单
  → PPT任务内简报、材料、分析与页面工作流
  → 制作PPTX → 渲染最终PPT预览 → 用户确认当前版本 → 下载
```

这是主要职责流，不表示每个请求都经过所有节点；计算补做、停止规则和PPT续接存在分支。

### 3.2 三层漏斗的实际边界

实现入口：`backend/agent/runtime/funnel.py`、`graph.py`。

- **规则层**：目前窄范围处理已有待办的明确取消，不凭关键词直接回答复杂政策。
- **上下文层**：确定性待办匹配，当前支持query_major_requirements和query_course的窄路径。要求待办有效、当前参数表达完整且实体唯一可信，不从历史实体堆中猜参数。
- **大模型加工具层**：处理复杂、含糊、复合或未满足前两层条件的请求；仍经过统一验证和工具执行。
- 尚未部署额外的小语义分类模型。路由只提出/提交动作，不直接授权执行。
- 普通问答具有最近消息、可信实体、待办及revision等历史状态，不是只有PPT有记忆；不是无限长记忆，也未默认启用联网历史摘要。

### 3.3 关键决定由谁负责

| 决定 | 负责人 |
| --- | --- |
| 当前任务、缺失输入、本人身份与引用材料范围 | agent/core/task.py的TaskBoundary及scope契约 |

当前成文输出为paragraphs，每段只含text、unit_ids、calculation_ids。模型不同时决定系统状态或填写复杂覆盖/布局表。引用存在、字段合法和数值检查通过，不等于完成逐句语义蕴含验证。

最新方向由用户明确纠正为“用PPT Master实际制作”。已执行本地托管适配，新任务默认renderer=ppt-master，不再继续扩建旧自有制作链路作为默认。设计见`docs/superpowers/specs/2026-10-25-ppt-master-host-design.md`；实现、检查及边界见`_work/phase8/ppt-master-host-20261025/实现与验证.md`。以下旧MVP能力和样例属于可复用基础，不代表新宿主已通过真实模型验收。

### 6.1 已实现功能

1. **制作简报**：目标、受众、预期理解/行动、页数/时长、必须保留内容、材料范围、外部补充权限。只有影响结果的缺口才补问。
2. **任务内材料包**：TXT/MD、DOCX、文字PDF、CSV、XLSX；保留标题、来源ID、定位、日期、适用范围，不写入公共知识库。
3. **按缺口取材**：材料充分可以0次补充；provided_only禁止外查；公开补充仅从用户指定候选URL读取。学校规定只用校园库或本校官方依据，不具备任意全网搜索。
4. **确定性数据分析**：count/sum/mean/share由Decimal计算，保留字段、过滤、分组、单位与分母；占比明确区分逐行合计和组内同一总量。数值不交给模型计算。
5. **可编辑PPT**：有限文字版式、原生柱状/折线图与表格，来源放页脚/备注和清单。
6. **指定页修订**：稳定slide_id、页面作用、正文和来源；支持替换、拆分、追加。未选页保持内容和ID；整体目标/受众变化则更新简报重新制作。
7. **版本交付**：材料替换使引用页待更新；每次新revision，旧下载凭证不能下载新草稿；实际预览后由用户确认当前版本，再下载。
8. **网页操作**：简报与多材料输入、数据分析、候选URL、最终PPT预览、选页反馈、确认及下载。普通请求30秒，制作/修订单独190秒。
