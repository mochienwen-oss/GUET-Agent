# 历史补强机制消融实验设计

日期：2026-10-26。**本文件是实验设计，不是付费 API 调用授权。** 本轮真实 API 请求数为 0。已有模型材料只作历史证据，当前离线回放不生成新的模型质量指标。

## 需要回答的问题

1. 对同一 API 模型而言，哪些限制会丢弃合理动作或正确正文？
2. 移除后任务完成、工具正确性、资料覆盖和事实正确性是否改善？
3. 收益是否以无据学校事实、权限越界或错误计算增加为代价？
4. 多层约束是否互相掩盖，以致单项消融无效但组合有效？

不得以代码行数、自由回答比例、HTTP200、合法 JSON 或引用 ID 存在代替质量指标。

## 已完成的本地机制实验

### 直答覆盖与负对照

实际运行 graph.agent_decide，模型结果用明确文本替身。当前分支对礼貌改写仍合成检索；仅在测试作用域将 safe_non_fact 改为接受候选文本后，改写可以直接交付。但同一改动也放行“奖学金截止时间为本周五”这一没有任何证据的学校事实。

这证明“全放开直答”不是可接受方案。该分支的特定 Qwen 9B 来源尚不清楚，所以该实验归类为通用路由边界调查，不能计入“确认旧模型补丁移除收益”。

### 旧单轮调用上限

相同 5 个已验证调用、相同总工具预算 6、同一执行节点、相同工具结果替身：

| 版本 | 发给执行节点 | 实际执行 | 观察结果 | 总预算消耗 |
| --- | ---: | ---: | ---: | ---: |
| A：重建旧 `calls[:3]` 规则 | 3 | 3 | 3 | 3 |
| B：本轮 API 执行路径 | 5 | 5 | 5 | 5 |

A 是按已读取源码重建的旧切片，不是保存的原始整进程快照；输入原始请求是 5 个，旧切片先丢了 2 个。另有测试发出超过总预算的调用，确认实际执行不超过总预算，每个未执行调用仍得到观察说明。没有放宽参数、实体或 Skill 执行权限。

结果只能说明动作不再被训练单轮形态静默截断；不能推算真实模型选择工具正确率、检索覆盖率或最终成文正确率。

原始本地输出：`_work/phase8/qwen-api-audit-20261026/routing-before.json` 与 `offline-ablation.json`。

### 错误映射回放

不连接模型或工具，仅嵌套现有 bounded_stream：受控上游 ValueError 被内层捕获并准备交付错误事件，但外层观察到共享取消标记，抛出 InterruptedError“请求已取消”。这验证了跨模块状态原因覆盖，来源不明，尚不属于已确认的 Qwen 补偿。数据见 error-mapping.json；取消、超时和恢复事件的未来修复应另设不收费的工程对照，无需为该程序错误先支付真实模型费用。

## 后续真实 A/B/C 的固定条件

- 使用相同 active_profile、API model、协议、生成参数、工具集合、知识库内容和来源版本；记录平台实际返回的模型标识，平台滚动升级不能默认为相同权重。
- 相同用户输入与历史、相同可执行工具权限、相同总预算和超时；不能一组加预算、另一组保留旧上限而把收益全归因于模型能力。
- 每个题目先明确期待的任务结果、允许的来源及不能出现的事实，评分条件在阅读本次输出前确定。
- 生成失败、重试、修复、工具故障全部计入；不得只统计完成的响应。不存在的服务不能当成“模型不会调用”。
- 当前原始 Git 版本不可取得。要精确比较旧规则，只在隔离实验分支恢复已证实的单项规则，并逐项说明，不冒称完整历史架构复现。
- 优先固定证据比较成文与交付；只有要测规划/检索的因素才运行完整工具链，以分开召回、编排与模型表达的影响。

| 组 | 唯一变化 | 问题与适用范围 |
| --- | --- | --- |
| A | 本轮 API 专用架构的完整业务约束 | 当前基线；无 Qwen 本地生成回退 |

| B2 | 只放宽直答后的白名单，改为经审查的任务/来源需求分流 | 通用路由实验，历史来源不明，不称 Qwen 补丁；严禁接受所有直答 |

B1 使用“恢复限制”作为方向相反的控制，因为本轮已清理该规则；描述结果时明确方向。B2/B3 是对已证实程序限制的实验，并不预设其设计初衷来自 9B。

## 输入覆盖

建议先定义 24 个不同任务，分为以下六类，每类 4 个；这里是待评审的试验规模，不是当前获准的 API 额度。

1. 普通交互：身份、能力、文字改写、给定文本总结；包含礼貌前缀和同义表达，不能只测已补过的问句。
2. 学校事实：明确制度、时效日期、缺资料、相似学校/学院范围；普通问题中混入具体学校事实的请求也必须受来源约束。
3. 工具参数：单主体、比较对象、同名实体、合法多调用；保留缺参数、额外字段和无权限工具负例。
4. 多轮任务：明确承接、改主体、纠错、转话题；不能把“我是哪一级”自动外推成后续全部资料的适用范围。
5. 固定证据成文：条件与例外、跨主体关系、完整流程、枚举汇总加逐项解释；使用旧 API 失败样本及未用于改规则的新例。
6. 状态与故障：工具失败、来源未核验、模型截断、结构修复失败；测试状态不能把这些统一说成“学校没有规定”。

每类保留至少一个未知资料或对抗负例。单次小样本只能形成定性证据；若要报告比例或稳定性，须事先确认重复次数与总费用。各组请求数按实际触发的规划/标题/修复/PPT 等生成调用计算，不能只按题数计费。

## 指标及判定方法

| 指标 | 定义与判定 |
| --- | --- |
| 任务完成率 | 完成预先规定的用户目标 / 全部执行任务；部分完成、失败和环境阻塞分别列明 |
| 工具调用正确性 | 需要执行时的工具、参数与对象均正确；漏调、误调、同参重复、正确调用被拒分别计数；无需工具题单独计算误调用率 |
| 检索覆盖率 | 已取得的必要事实或已知相关记录 / 题目需要的事实或记录；以原始依据人工核对，不用模型自评的 coverage 作真值 |
| 成文正确性 | 逐项检查主体、条件、数值、单位、例外及结论；来源真实和表述成立分开判；尽量盲评，不看组名 |
| 错误率 | 无据学校事实、错误适用范围、计算/来源错绑、结构终止、错误状态各自统计；不得只给混合平均值 |
| 工程成本 | 每题生成次数、修复次数、token、耗时及工具次数；只作代价，不作为正确率代理 |

有任一权限越界、来源造假或实际计算绑定失效的候选不得以普通交互改善抵消风险。也不能仅因候选更长、更短或更像自然聊天就判优。

## 费用与停止边界

本轮不执行这些真实 API 分组，不复用历史额度。后续必须先确认具体模型、允许外发的资料、总请求与 token/金额上限。任何重试和修复都计入上限；遇到服务或知识库不一致时先停止对应实测，不自动扩大采样。

本地报告会将“已完成机制实验”“历史真实材料结论”“待授权真实实验”分别记录，不将其加总成一个新的模型正确率。
