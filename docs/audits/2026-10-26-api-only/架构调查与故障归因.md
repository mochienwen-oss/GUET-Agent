# guet-agent 架构调查与故障归因

日期：2026-10-26。本轮范围已经用户确认：审计并清理 Qwen 专属运行链路；通用语义规则按证据处理；不调用付费 API，不部署服务器。

## 结论

旧模型的运行通道与模型能力补偿必须分开判断。前者包含显式切回 vLLM、旧采样参数、双提供方成文和模型权重启动项，已经没有当前 API 运行的必要；后者中，确有仍在限制模型的程序路径，但不能把所有权限、来源、参数及事实校验统称为旧 Qwen 补丁。

当前最明确的语义限制是：首次规划返回普通文本且没有证据时，graph.agent_decide 不直接采纳，而调用 safe_non_fact；未命中少量白名单表达就合成 search_regulations 调用。规划模型有直答机会，程序仍可能覆盖它。另一个有明确训练历史动机的限制是每轮只保留前 3 个工具调用，而总预算允许 6 次；本轮移除了前者，保留总预算及结果配对。

**不能断言本次清理已经提高真实 API 模型的正确率。** 本轮只进行了代码追溯、受控回放和不收费的协议/机制测试；真实模型 A/B/C 的任务质量指标尚未测量。

## 历史证据与不确定性

本地 Git main 没有任何提交，git log 无可用历史，相关源码也没有已跟踪版本。因此不能声称从 commit 找到规则的引入者或精确修改时间。证据来自当前代码注释、设计文档、旧验收材料和原始样本；未找到动机的规则标注“来源不明”。

项目历史实际出现过 Qwen2.5-7B、14B、Qwen3-8B 和标称 9B 的验收记录。比如 repetition_penalty 的注释明确对应 14B fp16 重复，而不是已证明针对 9B 的补丁。本文表名沿用用户要求，但每项单独区分是否能追溯到具体 9B。

- `docs/superpowers/plans/2026-10-24-evidence-centered-runtime.md`：旧 9B 的条件、范围和指标遗漏；后来同证据 API 成文比较。

## 当前调用路径与约束层

HTTP `/api/chat` → 会话租约与历史 → `graph.run_stream` → rules → 实体解析 → context/fixed_lookup → API 规划 → 参数/实体/Skill 校验 → 工具执行 → 证据台账 → 再规划或收尾 → 成文与来源绑定 → SSE 与持久化。

1. 模型之前：取消指令、待补参数接续、实体目录校验、已知课程/专业精确查询、成绩换算输入缺口。它们不是一个完整的通用意图分类器，但可以让部分请求不经过规划。
2. 模型规划：Registry 工具和 request_input 对话动作；正常规划不要求先输出整份业务 JSON。PPT 的 brief 属于具体工具输入，不能据此推断所有请求都有同样前置要求。
3. 模型之后：直答白名单可能覆盖文本；工具调用需要执行权限和可追溯参数；执行预算、重复调用和来源版本检查。
4. 成文：当前默认 grounded-body/1 只要求段落与来源/计算绑定；仍保留旧 claims/coverage 协议供明确选择。不能把旧协议的全部复杂字段当成当前默认 API 都必须填写。
5. 交付：范围、引用、已审核数值、完整枚举和计算记录检查；最多一次修复，失败后不发布无效草稿。它们不构成任意自然语言语义正确性的证明。

## “你好，你是什么模型”故障反向验证

实际位置：`backend/agent/runtime/graph.py::agent_decide`，`backend/agent/runtime/grounded_answer.py::safe_non_fact`，`backend/agent/runtime/answer_service.py::complete_answer`。

当前本地版本已经存在 _META_QUESTION 及对应回归测试。受控规划返回文本时，精确输入“你好，你是什么模型”现在不合成检索，而交付固定 SAI 身份说明；模型原文本同样被固定说明替换。因此不能把用户此前看到的故障直接宣称为当前版本稳定复现，也不能认定返回内容已经准确告知实际 API 模型 ID。

受控规划返回文本的当前回放：

| 输入 | 模型是否得到规划机会 | 程序实际处理 | 空工具结果后的交付 |
| --- | --- | --- | --- |
| 你好，你是什么模型 | 是，1 次 | 不检索，改为固定身份说明 | 不进入该分支 |
| 请说明你的能力边界和适用场景 | 是，1 次 | 合成 search_regulations | 本次检索未找到相关依据… |
| 帮我把“会议改为明天下午”写得更礼貌 | 是，1 次 | 合成 search_regulations | 本次检索未找到相关依据… |
| 学校奖学金申请的截止时间是什么时候 | 是，1 次 | 合成 search_regulations | 本次检索未找到相关依据… |

前两个普通请求的强制检索说明问题具有广泛性；最后一行是必须保留事实来源约束的对照。不能以“放行所有直答”作为修复，否则学校截止日期也可能无据发布。

回放使用明确的模型文本替身及模拟空工具结果，真实调用 agent_decide 与最终交付代码；没有运行真实检索，也没有询问真实 API。它证明代码会覆盖直答，不能证明真实 API 在原始故障中确实给出了正确回答。原用户会话的原始请求/响应未在本轮取得，因此 Prompt、模型首次选择与部署版本的实际责任尚不能唯一判定。

上述白名单仅在模型返回文本后执行；如果实际 API 首先提出工具调用，精确身份问句仍可能进入检索。没有原始 API 请求与响应，不能在 Prompt、模型工具选择和后置覆盖之间唯一归责。

当前 Prompt 的“事实只能来自本轮证据”“无可用证据时使用无证据分支”措辞覆盖过宽，会影响模型对普通对话的判断，是独立实验因素。它们是否由某个 Qwen 9B 失败直接引入，尚缺精确历史证据，不能凭现象推断。

## 本轮清理的行为边界

已将当前服务的规划、流式、成文、标题、相关性评估和 PPT 生成入口统一到 llm_api_client；空配置明确报错，不再允许切回本地生成。移除旧模型采样、固定模型/提供方配对及单独 DeepSeek 成文传输。部署和运行管理器不再声明或启动 vLLM；本地入口不加载生成模型权重。每轮前 3 个调用的训练截断已移除，但全局工具、步骤、重复、重试和请求时限约束保留。

未修改通用路由、主体范围、来源真实性、身份权限、Prompt 业务内容、事实检查和知识库数据。旧训练集、原始测试结果和离线历史工具不因清理当前运行通道而销毁；历史名字不代表仍被当前服务调用。具体审计结论见同目录审计表，后续实验见消融设计。

## 本地服务条件

当前本机能够读取 API 配置，所需密钥存在（仅检查有无，未输出密钥），但检查时本机 3306 和 6333 未监听，Docker 不可用。API 生成不需要远程 GPU，但完整应用仍依赖 MySQL、Qdrant、检索/精排模型及有效知识库。不能以 API 迁移为理由关闭这些业务依赖，也不能用空库或替身宣称完整服务验收通过。

新增 `scripts/local_api.py` 使用正常 `main:app`，默认本地回环地址、CPU 检索，加载同一 API JSON。启动不做收费模型探测；实际发送问题或制作 PPT 才可能产生 API 用量。本轮未启动可供真实问答的完整常驻服务，未部署服务器。

## 跨模块重复约束与耦合

| 问题 | 约束分布 | 实际影响与调整顺序 |
| --- | --- | --- |
| 直答与检索 | campus-v9 → model.decide → graph.agent_decide → safe_non_fact → complete_answer 的空证据分支 | 改 Prompt 并不能解除后置白名单；只放开白名单又不能保证学校事实有依据。先定义任务/来源需求边界，分组消融后再统一责任。 |
| 人群/资料范围 | scope → TaskBoundary → entity_validation → allowed_evidence → 正文契约/Prompt | 同一范围被不同层处理，但实体身份、资料适用性和表达限制是不同责任。需要判定哪一层做语义决定，哪一层只执行已确认边界，不能整体删除。 |
| 成文完整性 | question_brief → claims 或 paragraphs schema → structured_records → composition/grounded_answer → repair | 旧协议还要求覆盖/分类/布局；当前默认已精简。枚举唯一性曾跨渲染和记录检查误拒 API，实际修复涉及两个实现模块；仅改 Prompt 无法解决。 |
| 失败状态 | API 完整性异常 → registry ToolResult → decide_next/from_result → HTTP SSE → 保存的 FinalAnswer | 模型失败、工具失败、资料未核验与真正空检索须区分；当前部分兜底仍可能把上游错误选择显示成无依据。记录原始原因后再调整状态，不用文案掩盖。 |
| 参数与工具 | 模型 JSON Schema → Pydantic → 实体来源验证 → Skill 白名单 → 执行预算 | 类型、身份、权限和成本各有作用；字段顺序冻结是历史文本分布要求，并不意味着所有这些校验都是重复补强。 |

`llm_client.build_messages` 和 `llm/ctx_budget.py` 仍作为历史离线材料打包/训练审计辅助保留；当前主图不调用 build_messages，启动不再接入训练预算校验。不能把其中 8000 字符的默认值当成当前 API 证据包的实际截断上限。离线训练候选生成、LoRA 合并和旧训练/验收记录不属于当前服务生成调用链，本轮未销毁。

## 新确认的错误原因覆盖

`request_control.bounded_stream` 在内外两层同时使用时共享取消标记。用受控上游 ValueError 和内层错误事件恢复即可复现：外层最终抛出 InterruptedError“请求已取消”，原始错误原因没有成为交付事件。这是独立于模型质量和知识库召回的状态传播问题。来源尚不能追溯到 Qwen 补偿，不能按旧模型代码直接删除取消保护。

本地 HTTP 试验曾因测试替身遗漏 renderer 所需 hours 字段触发该覆盖；修正替身数据后另行重试。不能把该试验准备错误记为模型错误，也不据此认定原用户会话使用了同一失败路径。原始嵌套回放见 `_work/phase8/qwen-api-audit-20261026/error-mapping.json`。该通用请求控制问题留作后续独立修复，不扩大本轮专属链路清理范围。
