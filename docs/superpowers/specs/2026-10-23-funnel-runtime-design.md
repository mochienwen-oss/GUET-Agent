# 三层漏斗与成文职责收缩

用户已批准执行大纲，并要求跳过已有基线与质量材料的重复建设，从接口与统一提交入口开始。本轮只做本地实施，不连接已关闭服务器。

## 边界

- 规则层只接管独立、明确的操作；上下文层只承接可由当前消息与有效待办确认的任务；其余进入现有 Agent。
- 首批上下文接管仅覆盖 `query_major_requirements` 的单专业补参，以及当前消息已提供全部实体的 `query_course` 补参。缺失参数不从全局历史实体中猜取。不宣称这是经过训练的语义分类器。
- 三层建议统一经过主图提交，工具仍走原有 Skill、实体、scope、预算、判重、取消及 Registry 验证。显式 PPT 续接保持原入口。
- 取消仅清除已存在的问答待办，不取消其他任务或后台作业；持久化继续通过原会话乐观锁入口。
- 实际 CET 换算由运行图确认输入和可用规则后调用真实 calculate；所有调用可观察，不在成文器内隐藏计算。一般政策介绍与含金额的语句不触发实际换算。
- 最小段落成文作为可显式选择的本地候选；默认保留现有协议，未经真实 9B 验收不切换。程序派生段落编号和顺序，不要求模型自报条件分类和覆盖证明。来源、枚举、计算及范围检查保留，语义完整性仍不宣称被验证。
- 复用既有证据关系信息，不调整检索、训练、冻结资产或依赖。路由无法确认时回现有 Agent，不静默选中。

## 验证

只增加与改动直接有关的机制测试：取消持久化、待办补参、复杂目标回退、统一工具验证、漏调计算恢复、输入角色、预算终止、一般规则出口、段落来源约束与请求隔离。复用已有本地质量和服务器原始记录，不重建质量基线。

真实 9B 的自然表达、条件保留和语义分流收益保留到必要的服务器验收；本地模拟通过不能替代这些结论。
