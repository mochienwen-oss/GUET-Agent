# PPT Master制作工作流托管适配

用户已确认：PPT Master承担实际制作，项目复用材料、确定性分析、校园来源边界、任务归属、版本、预览及下载。此次“执行”授权本地实现及必要检查，不复用上一轮付费额度或自动部署。

新任务默认使用固定版本PPT Master的Default Generate路由。API模型通过任务内工具循环读取Skill/引用资源、读取真实材料与分析、写设计规格/锁/SVG/备注、执行允许的上游脚本；不调用现有固定版式制作器代替上游工作流。禁止开放任意shell/Python执行。上游完整包保持原样。

Stage 1与Stage 2通过现有网页中的策划确认面板提交，模型不能代填确认；设计复核等额外阻塞点也可由同一接口承接。任务保存对话与待执行工具，跨请求继续，不在单个HTTP请求内无界循环。沿用请求超时与取消控制。

新建任务以renderer=ppt-master标记，不破坏已存在的python-pptx任务。普通聊天对PPT的薄交接也进入该宿主。由PPT Master导出原生PPTX，再由宿主检查页数、页面来源关联、实际文件、最终PPT预览并返回draft。仍由用户确认当前revision才下载。

修订复用上游Generate Revision Round；复制当前工作项目为下一revision，限定目标页面，保留未选页源文件、稳定ID和最终页面内容。整体目标变化重新制作。图表/表格使用上游native-charts-and-tables契约，不借旧render.py补画。

首版支持现有文字材料和数据输入、包内设计/图标/图表/表格资源及指定候选公开来源。新增外部图像生成、全网搜索、动画/视频不在当前范围；不静默将这些请求当作已完成。包内独立确认/预览Web服务器不启动，改由项目网页提供对应确认及最终预览，并在宿主运行指令中明确这一适配。

完成条件：默认入口真实指向宿主；确认/继续/失败恢复和受保护交付可用；工具循环、文件归属、上游脚本调用、选页保留有定向检查；前端构建通过。实际付费模型效果与服务器部署单独说明，未执行不得宣称通过。
