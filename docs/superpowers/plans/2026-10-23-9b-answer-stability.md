## 2. 分离计算职责，固定工具契约

**位置：** `backend/agent/core/calculations.py`、`backend/agent/runtime/grounded_answer.py`；测试复用现有 grounded answers 测试。

- [x] 原文静态数值转述不因 claim_type/question_slot 为 calculation 就要求公式提示词。
- [x] 计算规则解释仍引用完整原文；实际运算采用程序授权记录。保留来源、范围和真实计算约束，不能简单关闭校验。
- [x] 从现有 score_conversion 拆出“识别支持规则”和“按显式输入执行”的能力；首版只支持现有英语成绩认定，不新建通用政策计算引擎。
- [x] 模型可调用参数固定为 rule_id 与 inputs；规则引用由本轮证据产生，系数、区间、取整和固定认定值由程序取得。
- [x] 计算记录包含 calculation_id、rule_id、inputs、matched_case、expression（仅实际运算）、raw_result、final_result、unit、rounding、source_refs 与 source_revision。
- [x] 输入只接受可追溯到当前问题或有效用户历史的明确值；多成绩含义不清或规则冲突时返回具体缺口，不取第一个数值。

**验收：** 静态“加4分”“上限100分”正常转述；非法规则、冲突规则、范围外数值、缺少输入不产出可用结果；区间边界与四舍五入结果正确；固定认定不伪造乘法。类型字段不再承担完整运算识别器的职责。

- [x] 图执行层注入当前请求的只读规则上下文；扩展调用入口使用可选内部上下文，模型 schema 不接收 state、来源正文或自行指定系数。其他工具行为保持。
- [x] 检索后的 observation 暴露本轮可用规则、输入要求与短引用，使规划模型能看到 rule_id；只放在最终成文包里会导致规划模型无法调用工具。
- [x] 检索取得规则后才能调用计算。不得在同轮并行的未完成检索上建立依赖；重复计算与总调用量使用现有预算，不默认提高全局上限。

- [x] 成文草稿引用 calculation_id，模型自然解释结果；校验对应结果、单位、输入和规则关联，允许不同措辞，不采用整段固定模板。
- [x] 接通后移除原 evidence_packet 自动从问题触发计算以及 renderer 覆盖整段正文的路径，避免双计算源。模型漏调时明确标为链路失败或缺口，不用隐藏自动计算掩盖。

**验收：** 模拟完整“检索—规则可见—调用—记录—自然成文”路径；未知/跨请求引用拒绝；工具算对但正文写错结果不能交付；额外解释允许但无据新增数值不能借计算记录获得授权；取消/超时/版本变更沿用现有约束。
