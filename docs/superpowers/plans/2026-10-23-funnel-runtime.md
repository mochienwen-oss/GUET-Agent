# 三层漏斗本地实施计划

**后续范围调整：** 用户要求优先完成可靠检索与成文；本计划勾选项代表本地实施与机制检查完成，不代表语义质量验收通过。后续以 `2026-10-23-retrieval-composition-focus.md` 为主线，通用漏斗扩展及校园业务接口暂缓。

> 按用户明确授权，由当前会话逐项执行；不创建代理任务，不重复基线质量评测，不操作服务器。

**Goal:** 减少 9B 的任务状态与工程记账职责，建立可验证的三层漏斗和计算闭环。

**Architecture:** 复用 ConversationContext 与主图，在现有实体解析后增加纯候选判断及统一提交入口；确定任务仍经过原工具验证。段落协议为独立可选候选。

**Tech Stack:** 现有 Python、dataclasses、LangGraph、Registry、Decimal、pytest；无新增依赖。

**Spec:** `docs/superpowers/specs/2026-10-23-funnel-runtime-design.md`

## 全局约束与审查重点

- 不把检索意图、会话动作和政策结论合为一个分类器；不继承未确认的历史参数。
- 复合/歧义请求回 Agent；待办必须有效；取消不能取消后台 PPT。
- 真实工具调用不能绕过 Skill、实体、预算、判重与来源版本。
- 一般规则阈值、金额、跨考试历史不能冒充实际成绩。
- 新成文协议不伪造覆盖完整性，不替换受测历史记录与默认协议。
