# 聊天式 PPT 工作区与公开搜索实施计划

按用户本轮完整规格直接实施，由三个子 Agent 分别负责 PPT 后端、PPT 前端、独立搜索适配；主 Agent 处理问答终止回复、密钥配置和接口衔接。用户要求先落地代码、再申请测试，本轮不运行任何测试、构建、服务重启、真实搜索或付费模型调用。

## 范围与接口

- 普通问答只增加三类检索终止回复。共享原生循环的 `on_tool_result` 可选回调仅在问答启用；PPT 不受无依据整轮终止规则影响。
- PPT 复用现有任务、原生循环、通用文件工具、外挂 Skill、真实确认和实际导出。内部模型历史与学生可见聊天记录分开保存。
- 新入口先 `POST /ppt/chat` 建立任务，再 `POST /ppt/task/{id}/messages` 发送首条需求及后续消息；现有状态接口返回聊天、选页、大纲、版本、资料与预览。选页通过任务内 selection 接口保存。
- 当前页只为模型提供讨论上下文，修改范围由用户意图和模型规划确定；执行时保留实际页面身份、版本、未选页面保护和真实确认记录。
- PPT 前端采用聊天、真实缩略图、实际画布三区；窄屏切换对话/页面。不加入没有实现的放映、撤销、拖拽或版本切换。
- PPT 专用 `search_web` 使用官方 Custom 独立 API；`read_webpage` 复用公开地址、跳转、超时和大小限制。只有实际读取的正文由制作宿主直接登记为当前任务材料。
- 用户密钥只写被 Git 忽略的 `backend/.env`，不进入前端、模型上下文或应用日志。按用户最新要求不查看账号额度；未核实免费保障时保持真实搜索不可用，不把配置密钥视为付费授权。

## 分工

- 主 Agent：`runtime/loop.py`、`runtime/graph.py`、`runtime/retrieval_reply.py`、`routers/chat.py`、密钥与本计划。
- PPT 后端：PPT workflow/host/存储/交付/制作 router，新聊天操作与来源登记。
- 搜索适配：`web_search.py`、`public_materials.py`、搜索配置与无密钥示例、官方文档说明。
- PPT 前端：工作区、PPT 组件、任务 API/类型/状态；不改普通问答界面。

## 代码落地后申请的最小验证

1. 三种问答终止结果只调用一次规划模型，不再调用成文或标题模型；闲聊仍可直答。
2. 模拟模型下的聊天恢复、确认续接、当前页/整份修改范围、真实文件与预览更新。
3. 搜索响应解析、未授权搜索阻断、来源登记、网页与 PDF 读取边界、日期与读取范围。全部使用明确的模拟响应，不发送真实请求。
4. Python 语法与导入、前端类型与构建；如获准再启动本地服务做界面检查。

真实搜索、GPU 推理、完整付费模型制作与服务器操作不包含在上述离线验证中。
