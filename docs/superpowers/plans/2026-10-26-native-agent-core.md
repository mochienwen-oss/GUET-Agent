# API 原生 Agent 核心实施计划

**依据：** 本会话已验收的九项方案大纲及随后明确的执行授权。

**目标：** 自然对话与工具执行共用一个 API 循环；保留现有检索；PPT Master 按需读取外部 Skill，通过限定范围的 B/C/D 制作，复用现有确认、预览和下载。

**架构：** 沿用现有 API 客户端、LangGraph 入口与任务服务。模型负责语言理解、工具选择和自然成文；运行时负责权限、工具参数、执行预算、真实文件和用户确认。

**技术：** Python、Pydantic、现有 HTTP API、Vue、原版 PPT Master。

## 已明确的边界

- 不运行测试、构建、编译检查、服务冒烟或真实模型请求。落地后单独列出必要验证并申请用户同意。
- 不部署服务器，不修改知识库、向量、BM25，不切换模型或思考模式。
- 不新增 A、G、网页工具、长期记忆、多 Agent 或新框架。
- 普通问答不提供任务文件写入或 Python 执行权限。
- 移除独立 calculate 及其强制预检；不强制模型用 Python 计算普通问题。
- 保留 PPT Master 原版流程、真实确认和实际导出要求。
- 所有实现由当前会话完成，不为计划另行增加批准环节。

## 实现时重点

- 模型直接文本不得被兜底改成检索；问题中带学校事实时仍明确提供来源政策。
- 工具失败不得伪装成空检索或“学校没有规定”。
- 模型不能修改后台配置、其他任务、Skill 包或伪造用户确认。
- 自然语言结束本轮与文件任务完成分别判断。
- PPT 修改保留非目标页面，下载仍验证归属和真实产物。

## 待批准验证

实施完成后提出最小离线验证集合；本计划不构成运行任何测试或付费 API 的授权。
