# SAI 桌面端（最小实现）

一个窗口里三段式：左侧导航（对话 / 我的演示文稿 / 最近对话），中间与 SAI 对话，右侧内嵌学校真实网页；
聊天区与网页区之间的分隔线可以拖动改变宽度。

## 启动

**先启动后端**（默认 `http://127.0.0.1:8080`），然后：

**双击 `desktop\start.cmd`**（推荐）。

脚本做三件事：
1. 清掉 `ELECTRON_RUN_AS_NODE` / `NODE_OPTIONS`（带上它们 Electron 会当纯 Node 跑，静默退出）；
2. 确保 `node_modules\electron` 已安装，把 Electron 运行时复制到 `%LOCALAPPDATA%\SAI\runtime`；
3. 把 `main.js / preload.js / campus/ / config.json / package.json` 同步到 `%LOCALAPPDATA%\SAI\app`，用它启动。

### 为什么不能直接 `npm start`

**Electron 33 在自身路径含中文时会立刻退出（码 3，零日志）**。实测同一个 `electron.exe`：

```
C:\Users\Lenovo\etest\electron.exe --version   →  v33.4.11   (exit 0)
D:\guet-agent\...\electron.exe --version  →  (无输出)    (exit 3)
```

项目原路径含中文，启动脚本仍将运行时和代码副本放在纯英文的 `%LOCALAPPDATA%\SAI` 下。
`desktop\` 里的文件仍是唯一来源——每次启动都会覆盖副本，**改 `config.json` 请改仓库里这份**。

> 如果你把项目整体挪到纯英文路径（例如 `D:\guet-app`），就可以直接 `npm start`，不需要这个复制流程。

## 布局与协作方式

```
┌──────────┬────────────────────────┬──┬──────────────────────┐
│ 侧边栏    │ 聊天（SAI）             │↔ │ 学校教务系统          │
│ 对话      │  · 真实进度：等待登录…   │  │ [返回][前进][刷新][×] │
│ 演示文稿  │  · 消息 / 上传 / 下载   │  │ ┌──────────────────┐ │
│ 新对话    │                        │  │ │ WebContentsView  │ │
└──────────┴────────────────────────┴──┴──────────────────────┘
```

- 右侧栏的**工具条和分隔线由 SAI 页面绘制**（`components/CampusPanel.vue`），学校网页本身是主进程的 `WebContentsView`，覆盖在页面量出来的矩形上。
- 页面每次尺寸变化都会把矩形发给主进程（`campus:bounds`），主进程只按这个矩形摆视图，不再自己算布局 —— 拖动分隔线、缩放窗口都不会错位。
- 关掉右侧栏或离开聊天页时，视图会被移除，不会漂在别的页面上。
- 学校页面可展开到整个工作区，支持手动缩放和适应宽度。默认隐藏 Electron 菜单栏。

## 配置 `config.json`

| 字段 | 说明 |
| --- | --- |
| `backendBaseUrl` | SAI 后端根地址。改这里即可切换本地/服务器，不要在别处再写一份。 |
| `campus.allowedHosts` | 允许在校内视图中打开的域名（后缀匹配，`guet.edu.cn` 覆盖 `v.guet.edu.cn`）。越界导航会被拦截。 |
| `campus.services.<服务>.startUrl` | 学校入口地址（已填桂电 CAS 登录地址）。留空时页面会明确提示"尚未配置"，不会假装已跳转。 |

## 登录后自动导航

任务创建后立即打开学校入口，不再等待模型额外回复一轮。用户自行完成账号、密码和验证码认证，程序不读取这些值。

导航器观察学校页面及其子框架。登录表单消失后，把可见的操作元素、标题和有限的教室结果表字段发送给当前 API 模型，由模型选择下一步。桌面端只执行当前观察中的元素操作，不执行模型提供的脚本或地址；每一步后重新观察。自动操作期间拦截非 GET 请求；学校查询如需提交 POST 等请求，需用户自行确认并操作。

找不到入口、信息不足或导航没有推进时，说明原因并暂停。用户可在对话中补充要求，或协助一步后点击“继续导航”；也可随时暂停。返回原聊天会话后可恢复任务入口，不自动恢复操作。

## 安全边界

- 校园视图：`nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`、**不注入 preload**。学校网页拿不到 SAI 令牌，也调不到主进程。
- 主进程 IPC 只接受 SAI 自身窗口的调用，并向后端核实登录用户及任务归属。学校登录会话按 SAI 用户独立保存，退出 SAI 时关闭原学校视图。
- 不接受模型下发的 URL、选择器或脚本；仅允许模型选取当前页面观察结果中的元素。
- 地址栏只显示地址的域名和路径，不显示登录票据等查询参数。学校的新窗口链接在同一受控视图中打开；未授权站点不能在学校视图打开。

## 状态回报

主进程在开始加载、加载完成、失败时通过 IPC 把状态发给 SAI 页面；`store/campus.ts` 收到后
1）在对话里显示「等待登录 / 已到达查询页 / 需要你接手 / 未能完成」，2）写回后端
`POST /api/campus/tasks/{task_id}/status`。**没有真实页面特征就不声称已到查询页**。

## 待验证范围（依赖用户本人登录后确认）

- 学校真实入口及模型对页面的识别
- 模型对查询条件和查询结果的理解
- 原生表单自动填写与学校控件的匹配情况

本轮尚未执行离线测试或真实登录验证。页面元素、标题以及筛选后的教室结果会发送至当前模型 API；密码、输入框现有值、Cookie 和网址参数不发送。自绘控件及特殊登录布局可能需要用户协助；不能据当前代码声称已完成真实空教室查询。

## 抓学校接口（调试用，默认关闭）

想把"在页面里点出来"变成"直接调接口"，第一步是知道浏览器到底发了什么请求。

打开开关（`config.json`）：

```json
"campus": { "trace": true }
```

然后正常启动、登录、走到空教室查询页并点一次查询。日志写在：

```
%APPDATA%\sai-desktop\campus-trace.log
```

每行一条 JSON，只记录 `XHR / Fetch / Document`：

```json
{"t":"...","type":"XHR","url":"https://.../api/xxx","method":"POST",
 "postData":"date=2026-10-31&period=3-4","status":200,"mimeType":"application/json",
 "body":"{\"rows\":[...]}"}
```

- **不记录** Cookie、Authorization、token 等请求头，避免凭据落盘；
- 响应正文只截前 4000 字符；
- 用完把 `trace` 改回 `false`，并删除该日志文件。

拿到日志后，按下面三种情况判断能不能脱离浏览器：

| 接口特征 | 可行性 | 建议做法 |
| --- | --- | --- |
| 只要登录态 Cookie（如 `JSESSIONID` / CAS 票据）+ 普通表单 | 高 | 在桌面端复用同一 session 调接口，结果解析后回传后端；凭据留在本机 |
| 请求带 `sign` / `timestamp` / 加密串 | 中 | 在**页面上下文**里执行页面自己的 JS 发请求，别自己重算签名 |
| 走 WebSocket 或动态渲染（无 XHR） | 低 | 继续用现在这套 DOM 驱动 |

无论哪种，**只做只读查询、控制频率、不要做写操作**（选课、报名、改资料），并且不要把 Cookie 传给后端或模型。
